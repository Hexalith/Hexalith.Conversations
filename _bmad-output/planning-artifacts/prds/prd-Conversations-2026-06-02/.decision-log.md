# Decision Log — Conversations Boilerplate Reduction PRD

Canonical memory and audit trail. Every decision, change, and override is recorded here as the conversation unfolds.

## 2026-06-02 — Activation & Intent

- **Intent:** Create (brand-new PRD). User confirmed via intent picker, despite a finalized Conversations feature PRD already existing. This PRD is a *separate* artifact targeting a refactoring initiative, not a rewrite of the feature PRD.
- **Topic:** Reduce boilerplate in the Conversations business-domain module. Domain projects should hold domain logic, not plumbing. Generic/common code should be consumed from, or promoted into, the technical modules (EventStore, FrontComposer, Commons, Tenants…).
- **Scope of "boilerplate" (user definition):** "Anything not specific to the Conversations module, or that can be generalized for reuse."
- **Reusability mandate (user):** Conversations is the pilot; the win is a thinner authoring surface every Hexalith business-domain module inherits. ("1 reusable.")
- **Stakes (inferred, pending confirm):** Internal developer-platform / framework hygiene. Users = developers authoring Hexalith domain modules. Form-factor = libraries/code.
- **Facilitator note flagged to user:** Much of this work is technical-how (which package owns what); that belongs in architecture/addendum, not the PRD body. PRD owns *what boilerplate must disappear, success criteria, scope/sequencing*.

## 2026-06-02 — Discovery grounding (3 Explore subagents)

Inventory grounded in real code. Key findings:
- Conversations ≈ 35,769 source LOC; ~50% (~18,000 LOC) is plumbing/boilerplate (categories "consume" + "promote"); ~48% genuine domain logic (keep).
- Three work-types emerged: **CONSUME** (Conversations hand-rolled what technical modules already expose), **PROMOTE** (boilerplate duplicated across domain modules with no shared home yet), **KEEP** (domain logic).
- Technical modules already expose substantial unused/under-used surface: `EventStoreAggregate<TState>`, `AddEventStoreDomainService()` (two-line host), `IDomainQueryHandler`, `IDomainProjectionHandler`, `IReadModelStore`, `ReadModelWritePolicy`, `IQueryCursorCodec`, ServiceDefaults, Aspire/Dapr module extensions, EventStore.Testing assertions/fakes, Commons `TypeMapper`/`FluentValidateOptions`.
- Cross-module duplication confirmed across Conversations/Folders/Projects/Memories/Tenants/Parties: ServiceDefaults, tenant-access projection handler, tenant-access DI, client HttpClient registration, Aspire/Dapr topology, JsonContext, domain-processor registration.
- Confirmed gaps (no helper exists yet): `ICommandContract`/`IEventContract`, polymorphic JSON registration helper, generic tenant-access projection handler, generic ServiceDefaults, generic client registration, generic Aspire/Dapr module base, tier-3 integration test harness, snapshot/upcasting hooks.
- Full digests retained by parent for drafting.

## 2026-06-02 — Fast-path scoping decisions

- **Delivery scope (user):** "Conversations + the promotions it needs." Deliver (1) Conversations consumes existing technical-module libraries, (2) common boilerplate promoted into technical modules + missing helpers built (only those Conversations consumes), (3) Conversations adopts them as the proof. Migrating Folders/Projects/Memories/Parties/Tenants = named follow-on, OUT of this PRD.
- **Working mode (user):** Fast path. Draft full PRD, tag inferences `[ASSUMPTION]`, iterate.
- **North-star (user):** BOTH equally weighted — (a) authoring a new domain module becomes dramatically thinner (measured: files/LOC for a minimal module + documented template), AND (b) Conversations' own boilerplate measurably cut. Counter-metric: no loss of behavior/contract stability.
- **Behavior-preservation contract (user):** External/public contracts + release-gate behaviors (tenant isolation, governance/audit pairing, idempotency, redaction replay, projection freshness) preserved and proven by conformance tests. Plumbing-only unit tests MAY be deleted with the plumbing they covered.
- **Assumptions stated to user (tagged in PRD):** stakes = internal developer-platform; Conversations treated as greenfield/pre-release; promotions land in EXISTING technical modules unless architecture proves a new one needed (open question for bmad-create-architecture); cross-submodule edits into EventStore/Commons/Tenants explicitly authorized (overrides project-context "scope to Conversations" default, since "promote" requires them).
- **Addendum:** technical-how (consume/promote library mappings, gap catalog, duplication evidence) routed to addendum.md to keep PRD capability-level.
