**Failure 2 — "projection version" still has two sources, exactly the divergence the anchor was meant to end.** The composite is "(projection version + redaction-policy version)", but "projection version" is defined nowhere, and the shipped contract offers two candidates: `ProjectionContractSchemaVersion` (a `SchemaVersion` — deterministic under rebuild but static, so temporally useless as an anchor) and `ProjectionCursor` (a "safe projection cursor equivalent" — temporal, deterministic only if derived from applied-event identity, which nothing states). ## The new discovery rule — **FAILED (critical)**

The rule: "the last complete overlay marker in this document must name the current sidecar head. Publishing a new sidecar authority version without an accompanying appended pointer amendment to this document is an authority-publication failure. A reader … resolves the architecture version from the last complete overlay marker and the checkpoint state from the sidecar head that marker names."

**Attack 1 — the marker cannot name what the rule says it names, by the rule's own grammar.** The Marker And Digest Grammar section — normative, in the same overlay — defines the full BEGIN attribute set as `(version, epic-authority, supersedes, predecessor block bytes and SHA-256, candidate-binding, hold)`. **There is no sidecar-head attribute**, and V13's actual BEGIN/END marker lines name no sidecar (only `candidate-binding=v9-authority-bundle-v1.json`, whose bundle does not yet contain the sidecars). The sidecar head is named only in the overlay *body*. Two letter-compliant machine readers: a marker-line parser (the reading v9 line 1841 explicitly commands: "determine current authority from the last complete architecture overlay marker") finds no head and either fails discovery or resolves through the candidate binding to a bundle that predates the sidecars; a body parser finds `v14-current-candidate-authority-v1.json`. Every future overlay that follows the normative attribute set will reproduce the omission. **Tightening:** add `sidecar-head=<path>` (and its SHA-256) to the normative marker attribute set.

**Attack 2 — "accompanying" has no atomicity bound, and the repository is currently the counterexample.** As of this review, commits `29c56fa` and earlier published the v13 and v14 sidecar authorities; the pointer amendment (the V13 overlay) exists only as staged bytes — the last *committed* overlay marker is V12 and names nothing. A compliant publisher can therefore hold authority forked indefinitely: sidecar committed, pointer "staged for the next publication commit" — a pattern V13 itself legitimizes by pinning proposal digests "of the approved bytes staged for the next publication commit". Two readers of the committed tree resolve checkpoint authority at E6-REMEDIATION/v12; two readers of the worktree resolve E6-CURRENT-CANDIDATE/v13 — in a repository whose own operating memory documents concurrent sessions committing mid-story. The Chain Hygiene section's "one publication commit … is a required completion step … and a precondition of any IR-0 rerun" is the only backstop, and it bounds nothing before IR-0. **Tightening:** require the sidecar publication and the pointer amendment in the *same commit* ("accompanying" = same committed tree), and state that a committed sidecar head newer than the last committed marker makes the effective checkpoint authority the *marker's* head (fail-closed), not the sidecar.

**Attack 3 — "authority-publication failure" has no cop.** No validator, blocker code, exit path, or owner detects or remediates the failure: the mandatory conformance validators byte-pin V9–V12 and parse nothing of V13 (verified in `PlanningAuthorityV9ValidationTest.cs`); the V12 preflight runs exactly those classes; no story or owner is tasked with the validator update the rule needs (the Quality owner owns validator rules, and V13 assigns them nothing). A rule whose violation the toolchain cannot see, published simultaneously with an instance of its own violation, is documentation, not a closure. **Tightening:** task the Quality owner (with a named artifact) to extend the planning validators to V13's marker grammar, head-pointer parity, and sidecar-chain digest checks before the publication commit is accepted.

**Attack 4 — dangling epic-authority identity.** `epic-6-authority-2026-08-18-v13` appears in the V13 marker and nowhere in the canonical epics document. Under v9's parity rule (validator "rejects any semantic … difference among the canonical epic block, architecture overlay, …") the eventual V13-aware validator must either FAIL on the missing paired epic overlay or accept an architecture overlay that unilaterally minted PM-owned authority. Publish the paired epic overlay in the same publication commit.
