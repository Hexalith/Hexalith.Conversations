## Verdict

**REVISE BEFORE THE PUBLICATION COMMIT — one critical internal inconsistency, three high enforceability gaps; everything mechanically checkable verifies.** The V13 block is substantively strong: every one of the eleven divergence closures targets a real finding from the gate, none invents a fact, and the delta survived every mechanical audit I ran — all four predecessor block digests (V9 18,270 B / `468621…`, V10 3,846 B / `893315…`, V11 3,042 B / `a97385…`, V12 6,075 B / `3050b3…`) and the v8 prefix digest (`7fd331…` over bytes 0–119264) recompute **exactly** under the digest convention V13 declares normative, which proves the recorded convention is the historically used one, not a retrofit; blank-line separation and the file-terminal LF match the declared grammar; all five named sidecar/proposal/view SHA-256s match current worktree bytes; the v14 sidecar really does pin the v13 sidecar's digest and the `151f9651…` candidate; the A1 current-proof decision file is `ACCEPTED`, release owner, 2026-08-09; both 2026-08-18 proposals carry release-owner APPROVED stamps; DC-7's key grammar matches the accepted Story 6.2 implementation (`ConversationProjectionReadModelKeys.cs`) token for token; and the factual refresh is accurate (Aspire `13.4.6` and Dapr `1.18.5` in `references/Hexalith.Builds/Props/Directory.Packages.props`, `src/Hexalith.Conversations.ServiceDefaults/` absent, `.slnx` includes `Client.Tests` and `Admin.Web.Tests`). Supersession discipline is respected: the scope sentence enumerates exactly what is superseded, the residual-force sentence covers the rest, and the one place V13 reinterprets earlier binding text (V12's "exactly 33 nodes") does so by explicit declaration, not silently. **However, the closure of C1 — the headline critical — contains a self-contradiction: the binding discovery rule requires the last complete overlay marker to name the current sidecar head, yet V13's own markers name no sidecar and the marker grammar V13 itself declares normative has no slot for one.** Read strictly, V13's publication is an "authority-publication failure" by its own rule the moment it lands. The block is staged but not yet committed, no successor digest pins its bytes, and V13 itself defers bundle rebinding to the pending publication commit — so the fix window is open and cheap. Fix F1 (and ideally F2–F4) before that commit; after it, the bytes are frozen and the defect becomes a permanent divergence for a V14 to close.

## Findings

### F1 — CRITICAL — The binding discovery rule contradicts V13's own marker grammar and markers; C1's closure is mechanically unexecutable

**Evidence.** Line 2416–2417: "the last complete overlay marker in this document must name the current sidecar head"; line 2419–2421: "A reader resolving authority from this document resolves … the checkpoint state from the sidecar head **that marker names**." But the V13 BEGIN marker (line 2360) and END marker (line 2569) carry `version`, `epic-authority`, `supersedes`, `v12-block-bytes`, `v12-block-sha256`, `candidate-binding=v9-authority-bundle-v1.json`, `hold=ACTIVE` — no attribute names `v14-current-candidate-authority-v1.json` (`candidate-binding` names the v9 bundle, a different artifact). And lines 2440–2442 declare the normative "full attribute set (`version`, `epic-authority`, `supersedes`, predecessor block bytes and SHA-256, `candidate-binding`, `hold`)" — which contains no sidecar-head slot, so every future compliant marker is also barred from satisfying the rule.

**Why critical.** This is the closure for C1, the gate's headline critical. A machine reader implementing the rule as written parses the last marker, finds no sidecar attribute, and either fails or falls back to guessing — recreating the exact discovery failure C1 described. Worse, "Publishing a new sidecar authority version without an accompanying appended pointer amendment … is an authority-publication failure" (2417–2419) combined with the marker-must-name requirement makes V13's own publication non-compliant with V13. (A charitable reading — "marker" loosely meaning "overlay block", whose body does name v14 with digest at lines 2399–2403 — rescues today's human reader but leaves the normative rule ambiguous for every future overlay and for the validator the rule exists to serve; ambiguity in the discovery rule is precisely what this amendment was chartered to eliminate.)

**Fix (concrete, still append-safe).** Before the publication commit pins these bytes: (a) add `sidecar-head=v14-current-candidate-authority-v1.json sidecar-head-sha256=e96c34dfdf7f2cd8619b75abc42aad40ab0d8606d3ab798bf2b9b58fac83da7f` to both the V13 BEGIN and END marker lines; (b) extend the line 2440–2442 attribute set to include `sidecar-head` and `sidecar-head-sha256`. Alternatively, reword the rule to "the last complete overlay **block** must name the current sidecar head and its SHA-256 in its Authority Relocation section" — but the marker-attribute route is the only one a validator can check without parsing prose, and it is what the rule's own wording already promises.

### F2 — HIGH — Epic-side amendments (DC-9, DC-10, DC-11) have no directed carrier into the PM-owned canonical epic authority; the required publication commit will fail its own parity validation

**Evidence.** The V13 marker declares `epic-authority=epic-6-authority-2026-08-18-v13`, and DC-10 adds an Epic 12 hard-entry condition (line 2525–2526), DC-9 names the Quality owner sole tier-membership decider (2520–2521), DC-11 disposes an obligation (2528–2530). Under V9's single-writer rule (lines 1907–1916) the canonical epic/story authority and obligation dispositions are Product-Manager-owned and human-authored ("The canonical epic v9 block remains the human-authored execution authority", 1896); the V9 bundle validator "rejects any semantic or digest difference among the canonical epic block, architecture overlay, graph, map…" (1900–1903). V13's chain-hygiene section (2543–2554) directs regeneration of "candidate-bound companions" only — generated projections, not the human-authored canonical epic block — and no sentence directs authoring the epic v13 amendment that would carry these three changes.

**Why high.** V9's epic table (line 2002) still says Epic 12 hard entry = "Story 6.2 done". At the publication commit V13 itself mandates ("a required completion step of this correction and a precondition of any IR-0 rerun", 2553–2554), the parity validator must compare the v13 architecture overlay against an unamended canonical epic authority and reject — stalling the mandated completion step. The defect is self-catching (the validator will find it), but it blocks the very commit V13 requires, and nothing tells the PM the authoring obligation exists.

**Fix.** Add one sentence to Chain Hygiene: "The Product Manager authors the paired `epic-6-authority-2026-08-18-v13` canonical amendment carrying the DC-9 tier-decider, DC-10 Epic 12 hard-entry condition, and DC-11 obligation disposition in the same publication commit; the parity validator gates the commit on it."

### F3 — HIGH — DC-7 ratifies a dispatch-ledger key with no tenant segment against the still-binding tenant-scope key rule, without declaring the exception

**Evidence.** DC-7 (lines 2504–2505) pins `projection:conversations-dispatch:<sha256-lowercase-hex(dispatchId)>` — no `<segment(tenantId)>`. Still-binding line 1105: "Durable stream keys, projection keys, cache keys, evidence keys, and worker job keys **must carry tenant scope**." The implementation DC-7 ratifies even claims the opposite of what its dispatch key does ("the caller bakes the tenant into every key", `ConversationProjectionReadModelKeys.cs` line 18–19). DC-7 simultaneously binds "the cross-tenant derived-key poison scenario" to this grammar version (2508–2509).

**Why high.** Two binding texts now disagree: a conformance assertion of line 1105 applied to the DC-7 contract fails on the dispatch key, and the poison scenario — whose whole subject is cross-tenant key collision — is bound to the one key in the grammar whose tenant scope is at best opaque (carried, if at all, inside the EventStore-owned `dispatchId` before hashing). If `dispatchId` is not tenant-qualified upstream, a cross-tenant dispatch-identity collision poisons the ledger, which is the bound scenario's exact failure mode. The grammar itself faithfully matches accepted, immutable Story 6.2 code — the defect is that V13 elevates it to a versioned contract without reconciling it with line 1105.

**Fix.** One sentence in DC-7: either "tenant scope for the dispatch-ledger key is carried inside the EventStore-owned stable dispatch identity, which is tenant-qualified before hashing" (if the platform contract guarantees it — cite where), or "the dispatch-ledger key is the single named exception to the tenant-scope key rule because the dispatch identity is globally unique and the ledger has no tenant read path; the poison scenario asserts non-collision across tenants." Silence is the one wrong option.

### F4 — HIGH — `conversations-vocabulary-v1` is load-bearing for DC-2 and DC-5 but nobody owns publishing it

**Evidence.** DC-2 (2466–2470): the redaction/hydration member sets, condition-to-state mapping, and indistinguishability policy "are owed by a versioned, digest-bound `conversations-vocabulary-v1` contract; no successor story that serializes trust, freshness, redaction, or hydration state may enter review before that contract is published." DC-5 (2493): "Anchor field names land in `conversations-vocabulary-v1`." No owner, story, epic, or checkpoint is named as the producer.

**Why high.** This recreates the exact orphaned-obligation pattern the gate flagged in H6 for ADR-001..010 ("no Epic 7–15 story owns authoring any of them") — which DC-8 fixes for ADRs with an authoring-at-implementation rule, while DC-2 reintroduces it for the vocabulary contract in the same overlay. The gate is fail-closed (stories stall rather than diverge), so C3 cannot silently reopen — but Epic 12's HP-OPEN work serializes trust and freshness state, so an unowned contract converts C3 from a divergence into an unbounded schedule blocker at the front of the critical path.

**Fix.** Name the vehicle in DC-2: e.g., "the Product Manager publishes `conversations-vocabulary-v1` as a candidate-bound companion of the V13 publication commit" or "authoring `conversations-vocabulary-v1` is an Epic 12 hard-entry condition alongside DC-10's interpretation resolution, owner: Solution Architect."

### F5 — MEDIUM — DC-1's usability criterion hinges on an unanchored "declared method"

**Evidence.** Line 2453–2454: "its paired P95 confidence half-width, **computed by the declared method** over the retained raw samples, is no greater than 5% of baseline P95." Declared where, by whom, versioned how — unstated. The envelope-revision record (2450–2452) is "named, recorded" but its schema is not said to carry the method.

**Why medium.** C2's core complaint was "two-ways satisfiable." DC-1 removes most of the ambiguity (frozen/versioned partition, paired re-measurement, numeric criterion), but a bootstrap CI and an order-statistic CI can disagree on the same raw samples exactly at the 5% boundary, so two compliant implementations can still return opposite usability verdicts. Fail-safe direction is at least right (disagreement surfaces as a dispute, not silent pass), hence medium not high.

**Fix.** "…computed by the method the envelope revision record declares and versions" — plus one line in Chain Hygiene adding the method field to the revision-record schema pinned at bundle regeneration.

### F6 — MEDIUM — DC-6 pins the audit-degradation default without naming the sentence it supersedes, leaving contradictory dead text in place

**Evidence.** DC-6 (2494–2498): "Non-governance commands and reads carry no audit-sink dependency and proceed during audit degradation. An ADR is required only to add continue-under-degradation behavior to a path that has an audit dependency." Still-binding pattern line 1201: "Non-governance behavior during audit degradation **requires an ADR before implementation**." The two say opposite things; DC-6 never cites line 1201, and the open question at line 605 is likewise not named as answered.

**Why medium.** The direction DC-6 picks is defensible (the literal old rule would demand an ADR for every read during an audit outage) and DC-6 is inside the enumerated supersession scope, so this is a declared closure in substance. But the gate's own low-severity roll-up already flagged "dead-in-place superseded rule text … the most persuasive wrong layer" as a recurring hazard [rubric F11], and DC-6 manufactures a fresh instance of it: a reader who lands on line 1201 (or 1225's ADR trigger) has no pointer to the reversal 1,300 lines below.

**Fix.** One clause in DC-6: "…superseding the pattern-section sentence requiring an ADR for any non-governance behavior during audit degradation, and answering the corresponding open architecture question."

### F7 — MEDIUM — DC-4's sole membership authority is an artifact that does not exist yet

**Evidence.** Lines 2484–2486: "The enumerated node-ID set in the **regenerated** candidate-bound graph projection is the sole membership authority." Chain Hygiene (2545–2554) defers all regeneration to the pending publication commit; until it happens, the graph pin is a future artifact and the only existing enumerations are the V9 projection (pre-sidecar) plus prose deltas.

**Why medium.** The gap is bounded — V13 makes the commit a precondition of any IR-0 rerun, and the composition rule itself (V9 canonical graph + enumerated overlay/sidecar deltas; verified: both sidecars do enumerate their node/edge deltas via `predecessors`/`successor` fields) is complete enough to regenerate deterministically. But between append and commit, "sole membership authority" refers to nothing, and a validator run in that window has no defined comparison target. Note for the record: DC-4's demotion of V12's "exactly 33 nodes" to a time-scoped derived check is an explicit, declared reinterpretation — correct supersession discipline, no finding.

**Fix.** Add "until that regeneration, the composition rule itself is the membership authority and no graph-parity verdict may be issued" (or equivalent explicit interim state).

### F8 — MEDIUM — The Open Dimension hold-lift precondition is prose-only, not wired into the hold-record validity rules

**Evidence.** Lines 2558–2562: the release owner "must decide it, defer it with a named owner, or delegate it … before any hold-lift decision." V9's mechanical hold-record validity conditions (2089–2096: validator PASS, candidate-matched IR-0 READY, explicit release-owner decision) are untouched, so a mechanically valid `LIFTED` record can exist with the operational envelope still undisposed.

**Why medium.** The obligation is on the same single actor who writes the hold record, so in practice the gap is small; but H3's remediation asked for a disposition *gate*, and this one is unverifiable by the machinery every other gate in this document uses.

**Fix.** One sentence: "at companion regeneration, the hold-record validator gains a required `operationalEnvelopeDisposition` reference (decision, deferral-with-owner, or delegation artifact) as a validity input."

### F9 — LOW — Marker-schema note excuses V10 only, and the END-marker schema is still unspecified

**Evidence.** Lines 2442–2443 excuse the missing `hold=` on "the V10 markers" — but V9's BEGIN also lacks `hold=`, and V9's END carries `version` only (no `epic-authority`, no `candidate-binding`), unexplained. The grammar section specifies the BEGIN attribute set only; V13's own END carries four attributes under no declared schema. **Fix.** Extend the note to "the V9 and V10 markers" and add one sentence declaring the END-marker attribute set (`version`, `epic-authority`, `candidate-binding`, `hold`, plus `sidecar-head*` per F1).

### F10 — LOW — Sidecar-recorded authority identities can contradict the marker, and the precedence is only implicit

The discovery rule implies marker-wins (reader takes architecture version from the marker, checkpoint state from the sidecar) but never states that a sidecar's recorded architecture/epic identities are generation-time provenance that can never override the last overlay marker.

**Fix.** One sentence in the Binding discovery rule. (Related, accepted-as-is: the v13-file/architecture-v13 name collision is disambiguated by the naming note at 2379–2382 for this pair, but nothing reserves the namespaces going forward — a v15 sidecar beside an architecture v15 re-runs the confusion.)

### F11 — LOW — Factual refresh: "module-internal-tier conformance project owed by Epic 9" presumes which identity the tier split keeps

The existing `Hexalith.Conversations.Conformance.Tests` references `Server` (verified in its csproj), which under v5's own construction (line 137–139: "Any oracle asset that binds it is non-portable by construction") makes the *current* project module-internal-tier; what the `.slnx` arguably lacks is the *portable*-tier project.
