## 2. What Went Well

1. **Behavior preservation held under the first real refactor load.** Despite 2.1–2.5 making the initiative's first-ever `src/` changes (host, aggregate base, cursor, store, projection seam), the contract-shape diff stayed **empty on every single story** and the conformance oracle never regressed (348→360). The Epic 1 oracle did exactly the job it was built for.

2. **The oracle grew stronger, not just bigger.** +12 net, monotonic, and several of those were *strengthenings*: Story 2.3's cursor scope now binds tenant/caller/filter/sort **pre-read**, so those mismatches fail closed with **zero reads** — strictly stronger than the deleted HMAC path. Growth came almost entirely from ledger-validation facts and fault-injection "teeth," characteristic of a behavior-preservation refactor.

3. **The assembly-scan seam-adoption pattern proved itself and was reused three times.** Born in 2.1 (host discovers Server-assembly handlers, no `Program.cs` edit), it was mirrored cleanly for `IDomainQueryHandler` (2.3) and `IDomainProjectionHandler` (2.5): add a thin handler to the Server assembly, prove the path with a dispatch-teeth test (matched reaches handler / unmatched surfaces the SDK miss), keep the domain logic untouched. A genuine reusable recipe.

4. **The decision-spine machinery absorbed a 57% mislabel rate with zero silent changes.** Four of seven stories corrected the upfront classification, yet every correction flowed through the Story 1.5 escape hatch + the `StoryNNStructuralDispositions` ledger + the inventory `changeLog` — append-only, frozen `approxLoc` never mutated, oracle never weakened. The Epic 1 spine was stress-tested hard and held.

5. **Reviews were adversarial, not rubber-stamp — and caught a real build break.** Story 2.2's review validated the "352 green" claim against the *working tree* and found the Release build was actually broken (submodule working trees drifted off committed gitlinks, dropping `Hexalith.Tenants.Client.Subscription` → CS0234). That CRITICAL would have shipped a false-green record under a credulous review.

6. **Reviewers preserved valuable work over literal AC adherence (2.6).** The dev added a sound `GenericValueConverterSkeletonTest` despite "add no test" guidance; the reviewer kept and documented it rather than deleting passing work — the right judgment call.

7. **Honesty about absent consume targets.** 2.6 and 2.7 could have manufactured busywork to "consume" non-existent shared surface. Instead they verified (greps against `src/` at specific Commons/EventStore gitlinks), recorded negative findings, and deferred the genuine work to FR-14/Story 3.6 — net-zero swaps where a swap would have weakened the oracle. Discipline over theater.

8. **The thin-adapter discipline kept domain logic single-sourced.** 2.5 kept `ConversationProjectionMaterializer.Project(...)` as the *single shared entry point* for both the new seam handler and the rebuild verifier — no duplicated replay loop, no sync-over-async shortcut.

## 3. Challenges & Growth Areas (systems, not people)

1. **Dev Agent Record count-drift recurred in 7 / 7 stories — Epic 1's #1 finding, committed-to and not fixed.** Every story's review corrected a stale count: 2.1 (525→527), 2.2 (183→185), 2.3 (530→535), 2.4 (545→548), 2.5 (556→561), 2.6 (587→603), 2.7 (357→360). This is the *exact* P1/P2 action item from the Epic 1 retro — "generate the record from the final `dotnet test` run as the last step." It was marked done as an `[x]` task each story yet **the count still drifted every time**, because QA gap-coverage tests land *after* the record is written and the record is not actually regenerated last. The action item treated a structural ordering problem as a checklist item. **This must become a mechanical/automated step, not an instruction.**

2. **Submodule gitlink drift was the dominant infrastructure hazard.** Surfaced as the lone CRITICAL in 2.2 (broke the Release build, contradicted a green claim), then found *again* in 2.3 (all four submodules drifted on activation). It was converted into a standing pre-build checklist item for 2.4–2.7 (verified clean each time) — good adaptation — but the underlying drift mechanism is still environmental and unguarded; it will recur in Epic 3's *cross-submodule promote* work, where drift is far more dangerous because those stories legitimately edit submodules.

3. **The upfront inventory was systematically optimistic about consumable surface.** 4/7 corrections (2.4 remove-and-replace→greenfield-adopt; 2.5 Promote→Consume; 2.6 Consume→defer-to-FR-14; 2.7 Consume→Keep-misclassification). The back-half stories effectively *became* the verification pass the Epic-1 inventory deferred. One error (2.7) was a genuine semantic conflation — Story 1.4 conflated "git repository" with "data-repository fake." The spine absorbed it, but the inventory's `targetCapability` claims were never reconciled against actual SDK/Commons gitlinks at authoring time.

4. **The read-store population gap is a genuine open architectural thread.** 2.4 built `ConversationProjectionReadModelWriter` but did not wire it; 2.5 correctly declined to drive it from the synchronous seam (no sync-over-async) and **explicitly flagged it as still-open**. Result: the production query side reads a read store that the projection path does not populate. This is the single most important unresolved item crossing into Epic 3 — and it was honestly surfaced, not buried.

5. **Composition/DI gaps repeated across seam adoptions.** The two-line host discovers the handler *type* but not its dependency graph — 2.3 (query boundary), 2.4 (read-store binding), 2.5 (handler registration) each had to add explicit `AddConversation*` registration. A pattern worth codifying so the next module author doesn't rediscover it three times.

6. **Test-parallelism race (Epic-1 T1) — resolved early, credit where due.** Story 2.1 closed the four-story-old `ReleaseEvidenceArtifactCollection` race via a shared non-parallel `[Collection]`, verified across 5 runs. The one Epic-1 HIGH liability that *was* paid down before it became a flaky CI gate.

7. **Admin.Web Playwright/Chromium lane failed on all 7 stories** — environmental (Chromium not installed), correctly not chased, but it means that lane provided zero signal all epic.

## 4. Key Insights / Lessons Learned

- **L1 — An action item that doesn't change the mechanism doesn't change the outcome.** P1/P2 (count drift) recurred 7/7 because "generate the record last" stayed an instruction the human/agent could mark done without the ordering actually being enforced. Lessons that depend on discipline at the exact moment discipline is scarce (end of story, post-QA) must be *mechanized*. (Epic 1's own L2 said this; Epic 2 proves saying it isn't enough.)
- **L2 — The inventory should verify, not assume, consumable surface.** Every label that assumed "a duplicate exists to remove" or "a promote target must be built" was wrong in 2.4–2.7. Future inventories should run the same greps each consuming story ran, *at authoring time*, and distinguish three states explicitly: *duplicate-exists-to-remove* vs *shared-surface-exists-to-adopt* vs *capability-must-still-be-built*.
- **L3 — Adversarial review against the working tree is non-negotiable.** Only 2.2's review re-running the build against actual gitlinks caught a false-green record. A review that trusts the record would have shipped a broken build. Validate claims against reality (git status, re-run suite, grep), never against the narrative.
- **L4 — Surfacing an open thread is a deliverable, not a failure.** 2.5's read-store population gap was flagged loudly with rationale (sync-vs-async) rather than papered over with a sync-over-async hack. That honesty is what lets Epic 3 plan for it instead of discovering it mid-story.
- **L5 — A frozen baseline forces honest accounting.** The frozen `approxLoc` / `plumbingBaselineLoc` repeatedly forced corrections through the `challenge/upheld` changeLog shape rather than a quiet relabel — which is *correct*: a real Consume→Keep relabel would have silently dropped the SM-1 denominator and broken reconciliation. The immutability constraint did its job.
