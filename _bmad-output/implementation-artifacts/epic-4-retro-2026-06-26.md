## 4. What Went Well

### The template is grounded in implementation

Story 4.1 did not invent a future Hexalith module shape. It validated the template against the actual post-refactor Conversations code:

- shared host through `AddEventStoreDomainService(...)` and `UseEventStoreDomainService()`,
- aggregate base through `EventStoreAggregate<ConversationState>`,
- query/cursor through `IDomainQueryHandler`, `AddEventStoreQueryCursorCodec(...)`, `QueryCursorScope`, and domain bounds,
- read model through `AddEventStoreReadModelStore()`, `IReadModelStore`, and `ReadModelWritePolicy`,
- projection through `IDomainProjectionHandler` delegation into the domain materializer,
- tenant access through the Commons tenant-access registration and Conversations-safe denial vocabulary,
- client, Aspire/Dapr, ServiceDefaults, serialization, telemetry, and testing/evidence through their live anchors.

### Optional and deferred boundaries held

Epic 3 warned that Epic 4 could overclaim the template. Epic 4 avoided that:

- FR-16 command/event metadata stayed optional instead of becoming mandatory public DTO coupling.
- `Admin.Web` and FrontComposer trust surfaces stayed outside the minimal skeleton.
- Governance workflows, publication subscribers, and operator UI were excluded unless a domain explicitly needs them.
- ServiceDefaults and Testing were counted only if present.

### SM-2 evidence is machine-readable

Story 4.2 created a JSON artifact that Epic 5 can consume without prose parsing. It exposes stable fields for `templateMinimal`, `preInitiativeEquivalent`, `comparison`, `oq2Status`, `measurementDate`, and source references. That directly prepares Story 5.3.

### Measurement honesty improved

The artifact records the 29-file / 468-LOC template minimal baseline as accepted, but labels the pre-initiative equivalent as estimated and low confidence. It computes reduction percentages from stated values without claiming OQ-2 is closed.

### Test fallback became operational practice

Both stories used the xUnit v3 executable fallback when VSTest socket creation was blocked. Story 4.2 made that guidance explicit in its story notes and recorded the environment-limited Admin Web lane without misclassifying it as a product regression.

## 7. Key Lessons

1. **A template is only useful if every instruction maps to live source.** Story 4.1's validation table is the right durable shape.

2. **Measurement artifacts need both machine fields and human caveats.** Story 4.2 gives Epic 5 structured fields while preserving the OQ-2 limitation in prose.

3. **Low-confidence estimates can be valuable if they are labeled.** The pre-initiative equivalent supports directional comparison but cannot close the target decision alone.

4. **Documentation stories still need adversarial review.** Both stories had non-code evidence drift that review corrected.

5. **Exact scaffold/reference tests are useful but require upkeep.** Story 4.2 exposed stale integration expectations left by earlier promotion work.
