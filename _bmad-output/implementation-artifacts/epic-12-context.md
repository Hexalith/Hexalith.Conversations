# Epic 12 Context: Universal Performance Restoration

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Restore correctness-preserving projection performance under the universal SM-C2 rule: all four frozen hot paths must independently produce usable, comparable evidence that candidate P95 is at most `1.05 * baselineP95`. Recorded baseline-era evidence fails three rows (`HP-APPEND` +20%, `HP-LIST` +330%, `HP-OPEN` +1761%; `HP-CREATE` -50%), blocking pilot acceptance and release attestation. List/open overhead stems from fail-closed cross-key validation, full-index generation work, and per-row page verification; optimization may remove only provably unnecessary fan-out or redundant work, never the checks themselves.

## Stories

- Story 12.1: Approve derived-key ownership, lifecycle, and rollback
- Story 12.2: Freeze the benchmark method and signal-quality algorithm
- Story 12.3: Implement correctness-preserving list/open optimization and migration behavior
- Story 12.4: Produce candidate-bound evidence and enforce universal SM-C2

## Requirements & Constraints

- **Universal SM-C2 gate:** Inventory `sm-c2-hot-path-inventory-v1` is fixed in order `HP-APPEND`, `HP-CREATE`, `HP-LIST`, `HP-OPEN`. Rows cannot be dropped, selected, or reordered. Every row requires usable signal and `postP95 <= 1.05 * baselineP95`; cost ceilings, disclosures, correctness rationales, owner acceptances, or recorded-only statuses never substitute. Changing the target needs a separate product decision.
- **Approved paired method (`sm-c2-measurement-method-v2` / `sm-c2-envelope-v2`):** Re-measure baseline (`29def441…`, EventStore `b2d34025…`) and candidate as a pair on one host under SDK `11.0.100`, runtime `11.0.0`, Release, `-parallel none -maxThreads 1`, with no `DOTNET_`/`COMPlus_` overrides or concurrent `dotnet`/`Aspire`/`daprd` processes. Only repetition constants may differ in fixture `f02c4b5d…`. Run 4 alternating sessions (`B,C,B,C,B,C,B,C`), 5 excluded warmups/session, 2,000 ops/sample, pooled per side (`HP-CREATE` 1200, `HP-APPEND` 400, `HP-LIST` 200, `HP-OPEN` 200); a failed session voids the pair. Retain all raw samples (no trimming, outlier removal, adaptive stopping, or rerun selection). Cold runs never replace warm results. Approval precedes first observation.
- **P95 & signal usability:** P95 is nearest-rank (`ceil(0.95*n)-1`). Signal uses the predeclared 10,000-resample `SplitMix64` percentile bootstrap on `P95(cand*) - P95(base*)`, passing iff half-width `<= 0.05 * baselineP95`. Missing or noisy rows are inconclusive.
- **Scale profiling:** Measure list/open handlers at 100, 1,000, and 10,000 rows (including page two) with store access and response processing (allocations, store ops, latency). Compare read vs. write costs before changing write paths, and report diagnostic size sweeps (warm/cold samples, tenant/page sizes, store mode, repetitions, allocations, P95) alongside the four-row verdict.
- **Scope & immutable provenance:** The benchmark covers warm in-process paths only; separate closed evidence is required against synchronous cross-service calls or unbounded history loads. Preserved absolute targets (e.g., 500 ms open P95) stay inactive unless activated. Baseline v1 and Story 6.2 evidence are immutable provenance only (never v2 inputs); keep the open baseline v1 fixture-hash disagreement (JSON `1a43bacc…` vs. Markdown `4838a5a1…`) surfaced without repairing or preferring either value.
- **Contract & correctness lanes:** Preserve filters, ordering, cursors, redaction non-leakage, freshness vocabulary, typed errors, forbidden/nonexistent equivalence, and response shapes; no UI scope. Unit, integration, and real Dapr state-store lanes must run real tests and pass before any performance verdict, covering invalid derived state (missing, duplicate, stale, advanced, malformed, misfiled, pending, inconsistent), tenant collisions, retries/idempotency, ordering/position conflicts, partial writes, latency, outages, poison records, concurrency, token stability, invalidation, legacy formats, interrupted rebuild, deletion, replay, and rollback.
- **Execution & evidence rules:** Bind committed `HEAD`, all root `.gitmodules` gitlinks (`check-root-submodules.py`), binary/source, raw samples, environment, and digests; JSON is authoritative, Markdown deterministic. Archived hold, planning-candidate (`PC`), ten-path gitlink, and V9 bundle prerequisites do not apply. Use producer-selected configuration and `net11.0`, recording legacy `net10.0`/Release substitutions. Build missing evidence scripts only when needed; run v2 final records only when required by the story spec; record waivers as waived, never PASS. Routine completion requires a green root build and individual maintained test-project runs.

## Technical Decisions

- **Derived-key lifecycle (ADR 0005, `conversations-derived-keys-v2`):** EventStore is the sole durable write authority. All seven Conversations-owned families (`conversation`, `tenant-index`, `dispatch-ledger`, plus the four resolution families) in the configurable read-model store are replaceable projection state with v1-identical key bytes (identity migration). Only the canonical named async projection route, the create-only `TenantCreated` initializer, and SDK interrupted-batch recovery may write them. Reads use `Get`/`GetMany` only and never materialize, backfill, or repair state. Only `dispatch-ledger` expires (`RedeliveryWindow`); `resolution-proof` outlives it. Deletion occurs only via operator full rebuild.
- **Optimization boundaries:** Stay strictly inside ADR 0005; adding a family, changing key bytes, adding a writer or read-side write, adding expiry, or reordering writes requires a new ADR and versioned grammar successor. `proposed` rows are commitments, not shipped behavior; implementing one must cite ADR 0005 with current evidence. Editing ADR 0005 voids its approval. If profiling justifies moving generation computation to writes, persist it in the existing conditional tenant-index update while keeping legacy formats, concurrency, replay, and rollback safe.
- **Consistency & freshness:** Projection completes only after conversation and tenant-index writes land; partial writes converge via idempotent retry. Because `dispatch-ledger` lacks a tenant segment, every access validates tenant, conversation, dispatch identity, and request fingerprint. Tenant auth fails closed before every read, write, and rebuild. Consume `ProjectionTrustState`, anchor comparability (including `HP-OPEN`) on `ProjectionFreshnessV1` (timestamps are display/lag only), and preserve list collection-completeness precedence (`Unavailable` for missing/contradictory indexes, `Rebuilding` for legacy/rebuilding/gap/incomplete-dispatch states, otherwise worst freshness across tenant-scoped matches before pagination, suppressing continuation if any row is withheld).
- **Rollback & harness:** Runtime rollback redeploys prior binaries and runs a full EventStore replay without reverse-writing derived state or repeating external side effects. Stories are independently reversible. The local AppHost stays a non-packable, non-publishable test fixture.
