## 2. What Went Well

1. **The behavior-preservation discipline held perfectly.** Zero `src/` changes across all five stories, verified by `git status` each time. The "gate-zero, no code moves" contract was never violated — exactly what a Phase-0 oracle epic requires.

2. **The oracle got materially *stronger*, never weaker.** Test count rose monotonically (248 → 348) and every review confirmed "assertion strength only holds or increases." The oracle now does its job.

3. **A genuine, high-value behavioral discovery (Story 1.2).** The headline finding: the 14 conformance suites were asserting a *synthetic scenario engine*, not the live `Server` decision code — a fail-open mutation rode green through the oracle. Backfilled live-decision-code characterization tests now turn the oracle **RED** under a deliberately-flipped tenant guard / dropped audit pairing / broken dedup / leaked redaction / suppressed-stale-downgrade. This is the single most important thing Epic 1 produced: the oracle is now trustworthy *for the refactor it exists to guard.*

4. **A reusable evidence-artifact pattern emerged and propagated.** The `ReleaseConformanceArtifactGenerationTest` / `PublicContractShapeSnapshotGenerationTest` shape (repo-root discovery → deterministic indented-JSON write → re-read + re-validate + content-safety scan) became the de-facto standard and was reused cleanly in 1.2, 1.3, 1.4, 1.5. Consistency made each subsequent artifact cheaper and more trustworthy.

5. **Honest measurement under pressure (Story 1.4).** The addendum's first-pass ≈18,000 plumbing-LOC (~50%) was **corrected down to 13,289 (37.15%)** with a recorded rationale (governance + hydration resolved Keep-now per OQ-3; Contracts/Testing domain surface attributed Keep). The team made the SM-1 denominator *smaller and more honest* rather than rounding to flatter the later Epic-5 reduction metric.

6. **Good judgment where a soft instruction conflicted with a hard guardrail (Story 1.3).** The story suggested *physically moving* the governance safety-net test into the oracle; the dev correctly **kept the original in place** (no-deletion guardrail dominates) and **added** the re-expression to the oracle. The right call, recorded.

7. **The autonomous senior-dev review loop caught real defects.** It was not rubber-stamping — 1.4's review found a genuine **AC1 violation** (a `Fixtures/**` glob re-included a file already carved to another row → file-level double-count, declared paths summing to 35,820 not 35,769) and a **validator giving false assurance** (compared path strings, not resolved files). ## 3. Challenges & Growth Areas (systems, not people)

1. **Recurring stale-test-count / documentation drift — the #1 systemic pattern (5 / 5 stories).** Every single story's senior-dev review had to correct numbers the dev recorded before the count settled:
   - 1.1: recorded 252 → actual **260**; File List missing `ReleaseBaselineValidationTest.cs`; staging inconsistency.
   - 1.2: recorded 286 / 281 → actual **294**.
   - 1.3: recorded 315 / +21 → actual **316 / +22**; an AC-strengthening edit left unstaged.
   - 1.4: documentation-adjacent (the double-count + the LOC reconciliation that only held on hand-entered numbers).
   - 1.5: recorded "9 facts / 340" → actual **17 facts / 348**.
   **Root cause (systemic, not individual):** the Dev Agent Record is written *before* the QA gap-coverage pass adds tests (1.5 went 9 → 17 facts *after* the dev wrote the record). The dev-writes-then-review-corrects loop structurally guarantees a stale count unless the record is regenerated last.

2. **A test-parallelism race has been deferred four times.** First observed in 1.2: `PublicContractShapeSnapshotGenerationTest` (writes a committed evidence file) races `ReleaseBaselineValidationTest` (reads it) under xUnit parallelism → transient `JsonReaderException` ("end of data"). Carried forward as "accepted, observed-once" through 1.3, 1.4 (where it actually flaked once during review), and 1.5. The committed file stays byte-identical, but this is **real test-infrastructure debt that will become a flaky CI gate** once Epic 2's heavier refactoring increases run frequency and parallel pressure.

3. **The oracle is still structurally coupled to the plumbing it must outlive.** `Hexalith.Conversations.Conformance.Tests.csproj` references `Hexalith.Conversations.Server`, and several suites (`TelemetryCardinality`, `TelemetryRedaction`, `ConformanceStatus` engine/fixtures) plus the three Story 1.2 `Live*` characterization tests bind to `Server.Diagnostics` / `Server.TenantAccess`. This is *coupled-by-design-retarget-in-owning-story* (telemetry → 3.3, tenant-access → 3.2, projection → 2.5, idempotency → 2.2), not a bug — but the oracle is not yet fully refactor-survivable, and the retarget obligation is now spread across multiple later stories.

4. **One carry-forward gap is unreachable from the oracle.** The live governance audit *gate* (fail-closed-on-sink-failure) is `internal`, visible only to `Server.Tests`. Story 1.2 pinned the *public materialized pairing invariant* as a proxy; 1.3 handed the internal gate to **Story 2.1** with rationale. It is logged, not closed.

## 4. Key Insights / Lessons Learned

- **L1 — Coverage ≠ assertion ≠ live-path exercise.** The defining lesson: a green conformance suite asserting a synthetic mirror of the decision code is *not* a behavior-preservation oracle. Test the **live** decision path, and prove it by fault-injection (flip the branch, watch a test go red). This is now baked into the oracle and must be the standard for every Epic 2/3 remove-and-replace.
- **L2 — Records must be generated last, or they will be stale.** 5/5 stories prove the human-curated count drifts. The fix is mechanical, not motivational.
- **L3 — Validators need teeth against *reality*, not internal consistency.** A validator that checks the artifact agrees with itself (path strings, hand-entered sums) passed while the live tree was double-counted. Validators must resolve to actual files / recompute from real data ("fold-and-recheck"). 1.5 internalized this with the fold-and-recheck `expectedPlumbingAfter` test.
- **L4 — Deferred test-infra debt compounds under refactor load.** The parallelism race was cheap to fix in 1.2 and is now a four-story-old liability heading into the highest-churn phase.
- **L5 — Honest baselines beat flattering ones.** Correcting 18k→13.3k now protects SM-1's credibility in Epic 5.
